# Internationalization

The frontend supports English (`en`) and Arabic (`ar`) with bundled `i18next` resources.

## Translation organization

Translations live in:

```text
src/i18n/
|-- index.ts
|-- format.ts
|-- en/translation.json
`-- ar/translation.json
```

Keys are grouped by application area, such as `auth`, `navigation`, `patients`, `visits`, `prescriptions`, `appointments`, and `settings`. Reuse `common` keys for shared actions, statuses, roles, priorities, and states.

User-entered and API-provided clinical content is displayed verbatim. Only application chrome and system-generated labels are translated.

## Language selection and persistence

Language resolution order is:

1. `doctor_clinic_language` in local storage.
2. The first supported browser language.
3. English.

Changing language through the login page, top navigation, or Settings calls `i18next.changeLanguage`. The application updates immediately without navigation or reload and writes the selected language to local storage.

The root `<html>` element is synchronized on every language change:

- English: `lang="en"` and `dir="ltr"`
- Arabic: `lang="ar"` and `dir="rtl"`

Arabic uses `ar-SA-u-ca-gregory-nu-latn`, which keeps Gregorian dates and Latin digits.

## Adding a language

1. Add the language code to `supportedLanguages` in `src/i18n/index.ts`.
2. Add language metadata to `languageOptions`.
3. Create `src/i18n/<code>/translation.json` with the same key structure as English.
4. Register the resource in the `resources` object.
5. Update `getDirection` and `getLocale` when the language needs different direction or formatting.
6. Verify every route, dialog, table, form, and responsive shell state in the new direction.

Use logical Tailwind utilities such as `start`, `end`, `ps`, `pe`, `ms`, `me`, `border-s`, and `border-e`. Add `icon-directional` to arrows or chevrons whose meaning should mirror in RTL.
